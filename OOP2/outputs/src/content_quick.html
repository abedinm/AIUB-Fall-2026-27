Inheritance

Four ideas, then three traces.

2.1class Child : Parent

class Dog : Animal gives Dog all of Animal's members. Use it only when the IS-A test passes (a Dog is an Animal). A class has exactly one parent class; a Car has an Engine is HAS-A, a field, not inheritance.

2.2Constructors: the parent runs first

Creating an object runs constructor bodies from the top ancestor down to the object's own class. : base(args) after a constructor header picks which parent constructor runs. A constructor without it silently calls : base(), the parent's parameterless one.

[[ex:e2_3]]
Trap

If the parent has only constructors with parameters, a child constructor without : base(...) does not compile: the hidden base() has nothing to call (error CS7036).

2.3protected and private

Child code can use the parent's public and protected members. private members exist inside the object but child code cannot touch them. Main sees only public.

2.4Hiding with new, and base.Method()

A child method with the same name as a non-virtual parent method hides it: the variable's declared type decides which one runs. new just says it is on purpose (without it: same behaviour, warning CS0108). Inside the child, base.Method() calls the parent's version.

Polymorphism

One rule decides every call. Learn it, then four ideas, three traces, four compile-or-not.

3.1A parent variable can hold a child object

Animal a = new Dog(); is legal because a Dog is an Animal. Keep two types apart: the variable's declared type (Animal) and the object's actual type (Dog).

The two-question rule for every call v.M()
  1. Does it compile? Look only at the declared type of v. No M there (or in its parents) means a compile error, whatever the object is.
  2. Which body runs? If M is virtual/abstract: start at the object's actual class and walk up; the first override you meet runs. Otherwise (not virtual, or only hidden with new): the declared type's version runs.

3.2virtual / override versus new

Parent marks the method virtual; child marks its version override: now the object decides, through any variable. The override must keep the same name, parameters, return type and access; overriding a non-virtual method is error CS0506.

3.3abstract and sealed

An abstract method has no body. A class with one must be abstract, cannot be created with new (CS0144), but can have fields and constructors. Every concrete child must override every abstract method (CS0534). sealed class cannot be inherited (CS0509).

[[ex:e3_5]]
Slide check

Week 5 slide 5 says an override may change access level and return type; the compiler rejects both. Slide 6 says an abstract class with a constructor "must be concrete"; abstract classes can have constructors, as above.

3.4Overloading versus overriding

Overloading: same name, different parameters; the compiler picks by argument type at compile time (exact match first, then char → int → long → double). Overriding: same signature in a child; the object decides at run time.
