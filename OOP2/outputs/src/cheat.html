Cheat sheet

Trace any program in four moves

  1. Start at Main; go line by line.
  2. new X(…): climb to the top ancestor, then run constructor bodies top-down. A constructor without : base(…) calls : base().
  3. v.M(): apply the two-question rule (below).
  4. base.M() always runs the parent's version, never the object's.

The two-question rule

  1. Compiles? Only if the declared type of v (or a parent) has M.
  2. Which body? M virtual/abstract: from the object's actual class, walk up; the first override wins. Otherwise (non-virtual, or hidden with new): the declared type's version.

Constructors

  • Not inherited; chained. Parent body first, own body last.
  • Write any constructor and the free parameterless one disappears.
  • Parent has only parameterised constructors → every child constructor needs : base(args).
  • Order with field initialisers: derived fields, base fields, base body, derived body.

Keywords

virtualparent allows replacement
overridechild replaces it; object decides
newchild hides it; variable decides
abstractno body; class can't be new-ed; children must override
sealedclass: no children. sealed override: no further overrides

thisthe current object; this.x = x
protectedclass + children only, not Main

Overloading vs overriding

  • Overloading: same name, different parameters; chosen at compile time by the declared argument types.
  • Overriding: same signature in a child; chosen at run time by the object.
  • Widening for overloads: char → int → long → double.

Does not compile

  • override on a non-virtual method CS0506
  • override changes access CS0507 or return type CS0508
  • new on an abstract class CS0144
  • abstract method in a non-abstract class CS0513
  • child misses an abstract override CS0534
  • inherit a sealed class CS0509; override a sealed method CS0239
  • abstract sealed class CS0418; private virtual CS0621
  • two parent classes CS1721
  • private member from a child or from Main; protected from Main CS0122
  • child-only member through a parent variable CS1061
  • parent → child without a cast CS0266
  • cast between siblings (Dog → Cat) CS0030
  • parent has no matching constructor for the hidden base() CS7036

Compiles, but…

  • Same-name method without new: hides, warning CS0108.
  • (Cat)a when a holds a Dog: crashes, InvalidCastException.
  • x = x; in a constructor: field stays default (warning CS1717).

Slides vs compiler

  • Week 5 slide 5: access level and return type "can be re-defined" when overriding. Compiler: both are errors.
  • Week 5 slide 6: abstract class with a constructor "must be concrete". Compiler: abstract classes can have constructors.
  • Week 4 slide 8: private members "not inherited". Precisely: inherited, but not accessible.
