1.1The shape of every program

[[ex:m1_skel]]
using System;Lets you write Console by its short name. Always the first line.
namespace FirstApp { … }A named group for your classes. Optional; exam code often has one.
class Program { … }A class is a container. All code lives inside some class.
static void Main(string[] args)The starting point. The program runs Main's lines from top to bottom, then ends.
{ }Braces open and close a block: a class, a method, a loop, an if. Every { needs its }.
Console.WriteLine("Hello");Prints Hello, then moves to the next line.
Console.Write("AI");Prints AI and stays on the same line. The next print continues right after it: AIUB.
Console.WriteLine();Prints nothing and moves to the next line. On a fresh line, that makes an empty line.
;Ends a statement, like a full stop ends a sentence.

1.2Variables and printing

A variable is a named box that holds one value: int age = 20; is type, name, =, value, ;. The type decides what the box can hold.

[[ex:m1_vars]]
  • + with text glues, left to right. "Sum: " + 2 + 3 → "Sum: 2" → "Sum: 23". But 2 + 3 + " is" adds the two numbers first → 5 is. Brackets go first: "Sum: " + (2 + 3) → Sum: 5.
  • int / int drops the decimals: 7 / 2 is 3. One decimal number makes it real division: 7.0 / 2 is 3.5.
  • % is the remainder: 7 % 2 = 1, 9 % 4 = 1, 8 % 2 = 0. i % 2 == 0 means "i is even".
  • {0}, {1} are slots filled by the values after the text, counting from 0: "{0} got {1}", name, grade → Nila got A.
  • Doubles print without extra zeros: 3.50 prints 3.5, 0.0 prints 0. bool prints True / False. \n inside text starts a new line.

1.3Casting and shortcuts

[[ex:m1_cast]]
  • Casting = converting a value to another type. Small to big happens by itself (implicit: int → double). Big to small needs the type in brackets (explicit): (int)10.75 is 10. It cuts the decimals; it never rounds.
  • A char is a number inside: 'A' = 65, 'B' = 66, 'C' = 67, 'a' = 97. So 'A' + 1 = 66 and (char)66 = B.
  • Shortcuts: x += 3 means x = x + 3 (also -=, *=, /=). x++ adds 1, x-- takes 1 away.

1.5Arrays

An array holds many values of one type, numbered from 0. a[0] is the first item, a[a.Length - 1] the last. new int[3] makes three zeros (a string array starts as nulls, a bool array as false).

2.1Class and object

A class is a blueprint: a form with empty boxes (name, ID, pay). An object is one filled-in copy, made with new. Staff is the class; Rahim's record is one object, Karim's is another. Each object keeps its own values.

The old Quiz-Mid question 10 marks

Write a class Staff for a university staff member with three main properties: Name, StaffID and BasePay. It needs two constructors: a default constructor that sets the name to an empty string, the ID to 0 and the base pay to 0.0, and a parameterized constructor that sets given values. Add a method display_info() that prints the details. Create one object with each constructor and call display_info() on both. (Wording shortened from the paper.)

The class recipe · six steps, always in this order
  1. Fields: private, one per piece of data.
  2. Properties: public, one per field: get { return x; } set { x = value; }
  3. Default constructor: no parameters; sets the starting values.
  4. Parameterized constructor: one parameter per field; this.x = x; for each.
  5. Methods: public void Show() prints; public double Calc() gives back a value with return.
  6. Main: make each object with new, then call its methods.

The answer on the next page is labelled with these six steps.

Try first 5 min

Before you turn the page: on paper, write Steps 1 and 2 for Staff (the three fields and the three properties), using only the recipe. A wrong attempt is fine. Then turn the page and compare.

2.2Every kind of constructor, and static

  • Default: no parameters. Parameterized: takes values. Copy: takes an object of the same class and copies its values. Static: static Student(), no access word, no parameters; runs once, by itself, just before the class is first used.

2.3A child class in one example

[[ex:m2_inh]]
  • class Student : Person: Student gets everything Person has. Read the colon as "is a kind of". This is the is-a relationship: inheritance.
  • : base(name) sends values up to Person's constructor. The parent's constructor body runs first, then the child's.
  • protected: like private, but child classes may use it too.
  • virtual in the parent + override in the child: the child's version replaces the parent's, even when the variable's type is Person.
  • base.Show() inside the child runs the parent's version; the child then adds its own lines.

2.4One array, many kinds: polymorphism

[[ex:m2_poly]]
Two questions for every call x.Method()
  1. Does it compile? Look only at the type written on the left when x was declared. Animal has no Purr(), so this fails even though the object is a Cat:
[[ex:m2_purr_err]]
  1. Which version runs? If the method is virtual and the child overrides it: the real object's version (a Cat says Meow). Otherwise: the declared type's version.

pets[1] is Cat checks the real object. (Cat)pets[1] converts it so Cat-only methods can be called.

The child recipe
  1. class Child : Parent
  2. Only the new fields, private.
  3. Constructor takes the parent's values plus its own: public Child(string a, int b, double own) : base(a, b) { this.own = own; }
  4. public override each method the story says works differently. Start it with base.Method(); to reuse the parent's part.
  5. Main: Parent[] arr = new Parent[n];, fill it with new Child(…), loop with foreach, call the method.

  • Assembly = one compiled project (one .exe or .dll). When the paper says "M2 has a reference of M1" or "a single solution with multiple assemblies", the namespaces are different assemblies.
  • Memory hook: internal = "my assembly". protected = "my children". protected internal = either one (OR). private protected = both at once (AND): my children inside my assembly.
  • Defaults: a member of a class or a struct with no modifier is private. A class itself (not inside another class) is internal. enum members are always public.
  • Encapsulation = keeping fields private and giving controlled access through properties and methods. Its main job: hide data.

3.4Value types, reference types, struct

Value typesReference types
int, double, char, bool, every struct, every enumclass objects, string, arrays, object
The variable holds the value. Copying copies the value.The variable holds a link to an object. Copying copies the link: both names reach one object.
[[ex:m3_struct]]
  • struct: a value type (the exam's answer for where it lives: the stack). Members are private by default. It can have fields, methods, properties and constructors with parameters. It cannot inherit from a class or another struct.
  • Printing an object or struct that has no ToString() of its own prints its type name, with its namespace if it has one: the course's Structt project prints Structt.StudentInfo.

3.5Boxing, var, dynamic, nullable, GetType

[[ex:m3_box]]
  • Boxing: value type → object (happens by itself). Unboxing: object → value type, needs a cast: (int)o.
  • var: the compiler picks the type from the value, at compile time. It must get a value on the same line, and its type never changes. dynamic: the type is checked only while running, so it can hold 10 and later a string.
  • int? can also hold null (nothing); printing null prints an empty line.
  • GetType() is a public method of Object, so every value has it. int is really System.Int32; string is System.String.

3.6enum: named constants

[[ex:m3_enum]]

Numbers are int by default, start at 0 and go up by 1. After a given value, counting continues from it (Mon = 10 → Tue = 11). Printing gives the name; (int) gives the number.

3.7ref, out, params

[[ex:m3_refout]]
(no keyword)The method gets a copy; the caller's variable does not change (NoRef left v at 10).
refThe variable must have a value before the call. The method may change it and the caller sees the change. Write ref in the call too.
outNeeds no value before the call; the method must give it one. Hands back extra results. A method may have several out parameters, in any position.
paramsThe method takes any number of values, zero included, collected into an array. Only one per method, and it must be the last parameter.

3.8Overloading, overriding, abstract, sealed

[[ex:m3_overload]]
OverloadingOverriding
WhatSame name, different parameter list (number or types)Same name, same parameters, in a child class
NeedsNothing special; works for methods and constructorsvirtual (or abstract) in the parent, override in the child
KindCompile-time (static) polymorphismRun-time (dynamic) polymorphism
  • A different return type alone does not make an overload.
  • A virtual method has a body; overriding it is optional. An abstract method has no body, sits in an abstract class, and every normal child must override it.
  • You cannot write new on an abstract class, but it can have constructors and normal methods. A sealed class cannot be a parent.

Part C · check before you hand in

  • Fields private, properties public: the "data security" mark.
  • Constructor parameters in the same order as Main passes them.
  • : base(…) on every child constructor.
  • virtual in the parent, override in each child: same name, same parameters.
  • Each rule in the story becomes a return condition; "and" = &&, "or" = ||.
  • Main: an array of the parent type, filled with new Child(…), then foreach.
  • Count your braces. Indent every block.

Part B · tracing rules

  1. Start at Main's first line. One box per variable; cross out and rewrite when it changes.
  2. Write stays on the line, WriteLine ends it, \n breaks it. {0} = first value after the text.
  3. "x" + 2 + 3 → x23; 2 + 3 + "x" → 5x. 7 / 2 = 3; 7 % 2 = 1; (int)9.9 = 9.
  4. Loops: one table row per pass: test, body, step.
  5. new Child(): constructor bodies run from the top parent down to the child.
  6. static fields: one shared value, kept from object to object.
  7. A call compiles only if the declared type has it. virtual + override → the real object's version; new or not virtual → the declared type's.
  8. Index past the end: crash (IndexOutOfRangeException).

Part A · keywords

  • static: one shared copy, use Class.X. A static method cannot use instance fields. Static constructor: once, before first use, no parameters, no access word.
  • const: value in the declaration, never changes, automatically static. readonly: declaration or constructor only.
  • ref: needs a value before. out: the method must assign it; many allowed, any position. params: last, only one, 0 or more values.
  • var: type fixed at compile time, must be initialized. dynamic: type at run time. int? can be null.
  • abstract: no new, can have a constructor; abstract method has no body. sealed: no children. virtual method has a body; overriding it is optional.
  • Destructor ~Name(): the GC calls it; no parameters, no modifier, one per class.

Part A · types and ideas

  • enum: named constants, int, starts at 0, +1 each; Mon = 10 → next is 11.
  • struct: value type, stack, members private by default, cannot inherit, can have constructors, methods, properties.
  • Value types: int, double, char, bool, struct, enum. Reference: class, string, array, object.
  • Boxing: value → object. Unboxing: object → value, with a cast.
  • Overloading: same name, different parameters, compile-time. Overriding: virtual + override, same parameters, run-time.
  • Is-a = inheritance; has-a = a field. Encapsulation = hide data with private. Default constructor = no parameters.
  • Every class inherits Object: ToString, Equals, GetHashCode, GetType (all public).
  • CLR runs the program; JIT turns IL into machine code; FCL = ready-made classes; GC frees unused objects.

Part D · how to answer

  • For each member: yes or no, plus the rule that decides it, in one line.
  • Other assembly: a child reaches only public, protected, protected internal; a non-child reaches only public.
  • Through an object variable (obj1.x) in a non-child: public, plus internal / protected internal in the same assembly.
  • Polymorphism: look for the same name with different parameters (overloading, compile-time) and virtual + override (run-time).
