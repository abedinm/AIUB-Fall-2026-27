Inheritance

The child-class recipe (D5, Q33)

[[codefile:recipe]]

Constructors

  1. new Child(...): climb to the top parent first. Constructor bodies run top-down: parent first, child last.
  2. : base(a, b) picks the parent's constructor and sends values up to it ("Nila" goes UP from Student to Person).
  3. No : base(...) written = a hidden : base(). If the parent has no constructor without parameters: error CS7036.
  4. Constructors are not inherited, they are chained. No return type, not even void.
  5. static constructor: runs once, before the class is first used. A static field is one shared box for all objects.
  6. Setting a field prints nothing. Only Write/WriteLine print.

Who can use a member

privateown class only. Inherited but not usable in the child: use the parent's public property (Cgpa, not cgpa)
protectedown class + children. Not from Main
internalanywhere in the same assembly
protected internalsame assembly or children
publiceverywhere
no modifiermember: private. Top-level class: internal

Cheat sheet 2 of 2

Polymorphism

A parent variable can hold a child object

Person p = new Student("Nila", 3.8); is legal: a Student is a Person. Declared type = Person (the variable). Actual type = Student (the object).

The two-question rule for every call v.M()
  1. Does it compile? Look only at the declared type of v. No M there (or in its parents) = error CS1061, whatever the object is.
  2. Which body runs? M virtual/abstract: start at the object's actual class, walk up; the first override runs. Not virtual, or hidden with new: the declared type's version runs.
overridenew (hiding)
Account a = new Savings(); a.M();Savings's MAccount's M
Savings s = new Savings(); s.M();Savings's MSavings's M
Decided bythe object, at run timethe variable, at compile time

Keywords

virtualparent allows replacement; has a body; overriding is optional
overridechild replaces it: same name, parameters, return type, access
newchild hides a non-virtual method; the variable decides
abstractmethod: no body, must be overridden. Class: can't new it, CAN have constructors
sealedclass: no children
base.M()runs the parent's M, wherever the line sits

Overloading vs overriding

Overloadingsame name, different parameters, same class. Compile time
Overridingsame name, same parameters, in a child. Run time

Casting

  • a is Savings: True if the object is a Savings (or its child).
  • ((Savings)a).Show(): treat a as Savings for this call.
  • Wrong cast (a holds an Account): compiles, crashes with InvalidCastException.
  • Parent to child with no cast: CS0266. Between siblings (Car to Truck): CS0030.

Does not compile

CS0506override on a method that is not virtual/abstract
CS0507/8override changes access / return type
CS0144new on an abstract class
CS0534child misses an abstract method's override
CS0509inherit a sealed class
CS0122private member from a child or Main; protected from Main
CS1061child-only member through a parent variable
CS7036parent needs arguments, child has no : base(...)

Same-name method without override or new: compiles, hides it, warning only.

Outside the topic, in case

var: type picked at compile time; dynamic: checked while running. Boxing: value type to object. enum values are int, starting at 0. const: fixed in its declaration; readonly: declaration or constructor.
