Block 1 · Tue 17:45–18:30 · 45 min

The C# you need to read class code

Ten concepts, about four minutes each. Answers on page [[page:key-b1]].

1.1Program, Main and printing

A C# program starts at the first line inside Main and runs downward. Console.WriteLine(x) prints x and then moves to a new line; Console.Write(x) prints x and stays on the same line.

[[ex:e1_1]] [[q:Q1.1|Predict the output|b1_q1]]

1.2Variables and arithmetic

Declare a variable as type name = value;. int holds whole numbers, double decimals, string text, bool true/false, char one character. int / int gives an int: the decimal part is cut off. % gives the remainder. If either side is a double, the result is a double.

[[ex:e1_2]] [[q:Q1.2|Predict the output|b1_q2]]

1.3Joining text with +

+ is evaluated left to right. Two numbers add; as soon as one side is a string, + joins text instead. Brackets force the arithmetic to happen first.

[[ex:e1_3]] [[q:Q1.3|Predict the output · a classic trap|b1_q3]]

1.4if, loops and arrays

if (condition) { … } else { … } runs one of the two branches. for (int i = 0; i < 3; i++) repeats with i = 0, 1, 2. foreach (int m in marks) visits every element in order. marks.Length is the number of elements; indexes run from 0 to Length - 1.

[[ex:e1_4]] [[q:Q1.4|Predict the output|b1_q4]]

1.5Methods

A method is written returnType Name(parameters) { body }. void means it returns nothing; any other return type means return hands a value back. In F(G(x)), the inner call G(x) runs first.

Here

static methods written next to Main (inside Program) can be called from Main by name alone.

[[ex:e1_5]] [[q:Q1.5|Predict the output|b1_q5]]

1.6Classes, objects, fields and new

A class is a blueprint; new Dog() builds one object from it. Fields are the variables each object carries. A class-type variable holds a reference to an object, so Dog b = a; makes b point at the same object, not a copy.

Precision

Fields you never set have default values: int and double are 0, bool is False, a string or object is null, and null prints as nothing.

[[ex:e1_6]] [[q:Q1.6|Predict the output|b1_q6]]

1.7Constructors

A constructor has the same name as its class and no return type. It runs automatically when new creates the object. A class can have several constructors with different parameter lists; new picks the one whose parameters match the arguments.

Trap

If you write no constructor, C# gives the class an empty parameterless one. The moment you write any constructor yourself, that free one disappears. Block 2 depends on this.

[[ex:e1_7]] [[q:Q1.7|Predict the output|b1_q7]]

1.8this

this means "the object this code is running on". When a parameter has the same name as a field, the plain name means the parameter, so this.name = name; copies the parameter into the field.

[[ex:e1_8]] [[q:Q1.8|Predict the output|b1_q8]]

1.9public, private, protected

public: usable from anywhere. private: usable only inside the same class, and the default when you write nothing. protected: usable inside the class and inside classes that inherit from it, but not from outside code such as Main.

[[ex:e1_9]] [[q:Q1.9|Which lines fail to compile? Main is in class Program.|b1_q9]]

1.10Properties: get and set

A property looks like a field from outside (s.Marks = 85;) but runs code: set on assignment and get on reading. Inside set, the keyword value is the value being assigned. public string Name { get; set; } is the short form with a hidden field.

Block 2 · Tue 18:30–19:30 · 60 min · Week 4 slides 3–23

Inheritance

Seven concepts, then five micro-traces from easy to hard. Answers on page [[page:key-b2]].

2.1class Child : Parent

class Dog : Animal makes Dog inherit the members of Animal: a Dog object can use them as if they were its own. Use inheritance only when the IS-A test passes: a Dog is an Animal. A C# class has exactly one parent class.

[[ex:e2_1]]

2.2Constructor order: the parent runs first

Constructors are not inherited, but they are chained. Creating an object runs the constructor bodies from the top ancestor down to the object's own class. A constructor that does not name a parent constructor silently starts with : base(), the parent's parameterless constructor.

[[ex:e2_2]]

2.3Choosing the parent constructor: : base(...)

Write : base(arguments) after a constructor's parameter list to choose which parent constructor runs and to pass it values. It runs before the child constructor's body.

[[ex:e2_3]]
Trap

If the parent has only constructors with parameters, every child constructor must call one with : base(...). Otherwise the hidden : base() has nothing to call and the code does not compile:

[[ex:e2_3err]]

2.4protected and private across the family

Code inside a child class can use the parent's public and protected members. private members still exist inside the object, but child code cannot name them. Code outside the family, such as Main, sees only public members.

[[ex:e2_4]]
Slide check

Week 4 slide 8 says private members are "not inherited". Precisely: they are inherited (the object contains them) but not accessible. Un-commenting either line above gives CS0122 … is inaccessible due to its protection level.

2.5Hiding a method with new

If a child declares a method with the same name and parameters as a parent method that is not virtual, the child's version hides the parent's. Which one runs is decided by the variable's declared type, not by the object.

Precision

The keyword new just says "I mean to hide". Leave it out and the code still compiles and behaves the same, with warning CS0108.

[[ex:e2_5]]

2.6Calling the parent's version: base.Method()

Inside a child, base.Method() calls the parent class's version of Method, even when the child has its own. Use it to extend the parent's behaviour instead of replacing it.

[[ex:e2_6]]

2.7HAS-A: composition

When one class keeps an object of another class in a field, that is HAS-A (composition), not inheritance. A Car has an Engine; a Car is not an Engine, so Car must not inherit from Engine (Week 4 slides 10–11).

[[ex:e2_7]]

2.8Precision corner (optional, rare in quizzes)

Order

Field initialisers (Log a = new Log(…)) run before the constructor chain moves up, so the full order is: derived fields, base fields, base constructor body, derived constructor body.

Polymorphism

One parent variable, many kinds of object. Ten concepts, five traces, five compile-or-not. Answers on page [[page:key-b3]].

3.1A parent variable can hold a child object

Animal a = new Dog(); is legal because a Dog is an Animal. From now on, keep two types apart: the variable's declared type (Animal) and the object's actual type (Dog).

[[ex:e3_1]]
The two-question rule for every call v.M()
  1. Does it compile? Look only at the declared type of v. If that class (or one of its parents) has no M, it is a compile error, whatever the object really is.
  2. Which body runs? If M is virtual or abstract, start at the object's actual class and walk up: the first override you meet on the way runs. If M is not virtual, or the child only hid it with new, the version seen from the declared type runs.

3.2virtual and override

Mark the parent's method virtual to allow children to replace it; mark the child's version override. Then a call through any variable runs the version of the actual object. (Week 5 slides 5, 8, 10)

Rules

The override must keep the same name, parameter types, return type and access level. You cannot override a method that is not virtual, abstract or override (CS0506), and private virtual is not allowed (CS0621).

Slide check

Week 5 slide 5 says the access level and return type "can be re-defined". The C# compiler rejects both: changing access is CS0507 and changing the return type is CS0508 (verified).

[[ex:e3_2]]

3.3override versus new, side by side

Same object, same calls, different keyword. override replaces the parent's version for everyone. new only hides it from variables declared as the child type.

3.4Polymorphic arrays and loops

An array of the parent type can hold any mix of children. Calling a virtual method in a loop runs each object's own version; a child with no override uses its nearest ancestor's version. (Week 5 slide 4)

[[ex:e3_4]]

3.5Abstract classes and methods

An abstract method has no body: just its signature and a semicolon. A class with any abstract method must be marked abstract (else CS0513). You cannot new an abstract class (CS0144), but you can declare variables of its type, and it can have fields, constructors and normal methods. Every non-abstract child must override every abstract method (CS0534).

Slide check

Week 5 slide 6 says "If abstract class has a constructor – it must be concrete". In C# an abstract class can have constructors and stays abstract; children call them with : base(...), exactly as below.

[[ex:e3_5]]

3.6sealed

sealed class X cannot be inherited (CS0509). sealed override on a method stops classes further down from overriding it again (CS0239). A class cannot be both abstract and sealed (CS0418). (Week 5 slides 7, 12)

[[ex:e3_6]]

3.7Overloading versus overriding

Overloading: same name, different parameter lists, usually in one class. The compiler picks the version at compile time from the argument types. Overriding: same signature in a child class; the version is picked at run time from the object. (Week 5 slides 9–11)

Matching

An exact type match wins. Otherwise the compiler uses a safe widening conversion: char → int → long → double. A long can widen to double but never narrows to int.

[[ex:e3_7]]

3.8System.Object and ToString()

Every class derives from System.Object without writing it. Console.WriteLine(obj) and "text" + obj both call obj.ToString(), which is virtual. If a class does not override it, it returns the class name. (Week 5 slide 7)

Precision

The default returns the full name, including any namespace: inside namespace Lab it would print Lab.Plain. These examples have no namespace.

[[ex:e3_8]]

3.9Casting between parent and child

Child to parent (upcast) is automatic. Parent to child (downcast) needs (Dog)x, and it crashes at run time with InvalidCastException if the object is not really a Dog. x is Dog tests first; x as Dog gives null instead of crashing. A cast between sibling classes such as Dog to Cat does not even compile (CS0030).

[[ex:e3_9]]

3.10Precision corner (optional)

Virtual in a constructor

A virtual call inside a base constructor already runs the derived override, before the derived constructor body has run. Field initialisers have run (n = 5), constructor assignments have not (m is still 0).
