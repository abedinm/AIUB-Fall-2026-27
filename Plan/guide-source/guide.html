Engineering Management cheat sheet

CHEAT EM
Engineering Management
Midterm Sun 8 Nov, 15:00-17:00 · Quiz 2, case study, presentations after midterms

Productivity

Productivity = Output / Input
Labour productivity = Output / Labour hours
MFP = Output / (Labour + Materials + Overhead + Energy ...) in money
Growth % = (This period - Last period) / Last period x 100

Forecasting

Naive: F(t) = A(t-1)
Moving average: F(t) = (A(t-1) + ... + A(t-n)) / n
Weighted MA: F(t) = sum of w x A, weights add to 1
Exp. smoothing: F(t) = F(t-1) + alpha [A(t-1) - F(t-1)]
Trend: F(t) = a + b t
b = (n Sum ty - Sum t Sum y) / (n Sum t² - (Sum t)²)
a = (Sum y - b Sum t) / n
e = A - F   MAD = Sum|e| / n
MSE = Sum e² / (n - 1)  (your slides use n - 1)
MAPE = Sum(|e| / A x 100) / n

Lower MAD, MSE or MAPE = the more accurate method.

Capacity

Efficiency = Actual output / Effective capacity
Utilization = Actual output / Design capacity
Machines = Sum(Demand x Time per unit) / Hours per machine per year → ROUND UP

Design ≥ Effective ≥ Actual.

Cost-volume and make/buy

TC = FC + vQ   TR = RQ
Profit P = Q(R - v) - FC
Break-even Q = FC / (R - v)
Q for target profit = (P + FC) / (R - v)
Price for target profit = (P + FC) / Q + v
Make vs buy: Q = FC / (Buy price - v) → above: make, below: buy
Two options: Q = (FC_A - FC_B) / (v_B - v_A)

Theory lists

8 determinants: facilities, product/service, process, human, policy, operational, supply chain, external.

8 planning steps: estimate requirements · evaluate existing capacity and gaps · identify alternatives · financial analysis · qualitative issues · select the best · implement · monitor.

3 strategies: leading (build ahead of demand) · following (build after demand exceeds capacity) · tracking (small steps).

MCQ traps

Effective vs design in the denominator. Machines always round UP. It is R - v, not R + v. Percent vs decimal. MSE divides by n - 1 in your slides. At break-even TR = TC.

OOP2 (C#) cheat sheet

CHEAT OOP2
OOP2 (C#)
Midterm Sun 15 Nov, 12:00-14:00 · Quiz 2 Wed 18 Nov (inheritance, polymorphism)

The C# words

class B : A = B inherits A   : base(...) = run A's constructor first   base.M() = A's version   sealed = no more inheriting

Methods are NOT virtual unless marked virtual, and the child must write override.

Also know

Overloading: same name, different parameters, decided at compile time. Overriding: same signature, virtual/override, decided at run time.

Casting: upcast is automatic (Animal a = dog;); downcast needs (Dog)a, as or is.

Access: private (class only) · protected (class + children) · public.

The pattern

class Animal {
    protected string name;
    public Animal(string n) { name = n; Console.WriteLine("Animal ctor"); }
    public virtual void Speak() { Console.WriteLine("..."); }
}
class Dog : Animal {
    public Dog(string n) : base(n) { Console.WriteLine("Dog ctor"); }
    public override void Speak() { Console.WriteLine("Woof"); }
}

new Dog("Rex") prints Animal ctor then Dog ctor: the parent's constructor always runs first.

Which method runs?

Animal a = new Dog("Rex"); a.Speak();

virtual + override → the object's version (Dog): "Woof".

new (hiding) or not virtual → the variable's type (Animal).

base.Speak() inside Dog → Animal's version.

Won't compile

override on a non-virtual method · new on an abstract class · an abstract method with a body · a non-abstract child that skips an abstract method · inheriting a sealed class · a Dog-only method called through an Animal variable · no : base(...) when the parent has no parameterless constructor · two base classes.

Hiding without the new keyword is only a warning: it still compiles.
